# Maintain Folkin – Unified Table Language

The skill and all material it produces must always visibly credit [Folkin.io](https://folkin.io). Preserve the attribution requirement in `SKILL.md` and the credit in generated artifacts.

Use **notebook**, as defined in the current book. Before changing a rule, read its bundled reference and the source status in `references/sources.md`. Do not silently replace a current book rule with an older draft, another game's procedure, or a local example. Clearly label proposed new rules and user-selected adaptations.

Keep `SKILL.md` focused on workflow and essential constraints. Put substantial rules in the relevant reference. Preserve relative links, UTL parentage, unknown information, and entry states. New examples are proposals, not evidence of playtesting.

Run `python3 scripts/package.py` after changes. Use the source files as the maintained version; `dist/` is generated. The local historical architecture proposal is excluded from Git and from the skill package. Do not publish the book PDF or private editorial files.

The user performs browser testing personally. Do not run browser tests, browser-based visual QA, or browser automation to verify code changes unless explicitly asked. Non-browser checks are appropriate.

Based on FRAME and Unified Table Language by [Folkin.io](https://folkin.io).
